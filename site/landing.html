Prioritise your backlog by value for effort

rewelo ranks tickets with the relative weight method: score each one for benefit, penalty, estimate and risk, and it tells you what returns the most for the least. From the command line, or from your AI assistant through MCP.

Read the docs View on GitHub

Command line

npm install -g rewelo
rw project create Acme
rw ticket create --project Acme --title "Login page" \
  --benefit 8 --penalty 5 --estimate 3 --risk 2
# … and three more tickets
rw ticket list --project Acme --sort priority

What you get

Title          | B |  P | E | R | Value | Cost | Priority
-------------- | - | -- | - | - | ----- | ---- | --------
Password reset | 5 |  8 | 2 | 1 |    13 |    3 |     4.33
Login page     | 8 |  5 | 3 | 2 |    13 |    5 |     2.60
Audit log      | 3 | 13 | 8 | 5 |    16 |   13 |     1.23
Dark mode      | 3 |  1 | 5 | 2 |     4 |    7 |     0.57

The password reset comes first: as much value as the login page for three fifths of the cost. Every command is in the CLI reference.

MCP server from npm

npm install -g rewelo
claude mcp add rewelo -- rw serve

That's Claude Code; the MCP guide has the configuration for Claude Desktop and other clients. rewelo is in the MCP Registry as io.github.sebs/rewelo.

MCP server in Docker

docker run --rm -i --init --cap-drop=ALL \
  --read-only --memory=256m \
  -v rw-data:/data ghcr.io/sebs/rewelo serve

Add it to Claude Desktop or Claude Code as described in the MCP guide.

How the method works

Value = Benefit + Penalty
Cost = Estimate + Risk
Priority = Value / Cost

Every dimension uses the agile Fibonacci scale: 1, 2, 3, 5, 8, 13, 21. Weights let you emphasise what matters to you, and relative weights compare a ticket with the whole backlog or with a tagged subset. The calculations page has the details.

Flow and forecasts

A cumulative flow diagram, throughput per week, cycle-time percentiles, the work in progress by age, and the dates by which the backlog is likely done, simulated from the pace you actually had.

A live dashboard

One self-contained page: health, flow and forecast, the ranking, what changed in it and why, and the dependencies, with priority inversions in red. --watch keeps it current; in Claude Desktop and claude.ai it shows in the chat and refreshes itself.

Checks on the scoring

Whether your estimates predict how long tickets take, which scores have gone stale, and what moved in the ranking since a date, with the reason for each move.

Tags, not fields

prefix:value tags such as state:wip or feature:auth organise tickets, one value per prefix, with every change in an audit log.

Your data, one file

Everything lives in a single SQLite file via Node's built-in node:sqlite. Export and import CSV or JSON, including full history.
