# ADR-005: SQLite (node:sqlite) as Database

## Status

Accepted. Supersedes [ADR-003](003-duckdb.md).

## Context

ADR-003 chose DuckDB as an embedded database. In practice the `duckdb` npm package became the main source of friction:

- It is a native module. When no prebuilt binary exists for the running Node.js version (e.g. Node 26), `npm install` falls back to compiling DuckDB from C++ source, which is slow and failed on developer machines.
- Its build toolchain (`node-gyp`, `tar`, `glob`, ...) accounted for every known vulnerability reported by `npm audit`.
- The analytical strengths that motivated ADR-003 are not needed at our data sizes (hundreds to low thousands of tickets per project).

Node.js ships SQLite as the built-in module `node:sqlite`. It is available without flags or warnings from Node.js 24 onward.

## Decision

We use **SQLite via `node:sqlite`** as the sole database engine and remove the `duckdb` dependency.

- Database files use the `.db` extension; the default is `./relative-weight.db`.
- Ids use `INTEGER PRIMARY KEY AUTOINCREMENT`, timestamps are ISO-8601 UTC text (`2026-01-31T12:00:00.000Z`), UUIDs are generated by a SQL column default, and enums are `TEXT` with a `CHECK` constraint.
- Foreign keys are enforced via `PRAGMA foreign_keys = ON` on every connection.
- The minimum supported Node.js version is 24; CI and the Docker image use Node.js 26.

## Consequences

- No native modules: installs are fast and identical on every platform and Node.js version.
- `npm audit` is clean after removing DuckDB's build toolchain.
- Existing `.duckdb` files cannot be opened. Users export each project with rewelo 0.4.x (`rw export json`) and import it into a new `.db` file (`rw import json`). The export covers tickets and tag assignments; revision history, tag change logs, relations and weight configurations are not carried over.
- Timestamps have millisecond instead of microsecond precision. Queries that order by time need an explicit tiebreaker (e.g. the row id).
- Users can inspect their data directly with the `sqlite3` CLI.
